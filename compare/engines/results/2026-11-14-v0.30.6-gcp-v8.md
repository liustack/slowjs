# V8 benchmark suite: run 2026-11-14-v0.30.6-gcp-v8

- Run on 2026-11-14 on a machine that is not the one of [2026-11-06-v0.30.1-gcp-v8-c](2026-11-06-v0.30.1-gcp-v8-c.md), so its numbers cannot be compared with that file. The three sides ran in one session, here.

- liustack/quickjs v0.30.1: tag `v0.30.1` (5e99b850), run by the `cmd/jsbench v8` of that tree, built in its `compare/engines` with `-tags eng_liustack -pgo=off -trimpath`, Go 1.27.4, GOMAXPROCS=1
- liustack/quickjs v0.30.6: main at 78a90364, built and run the same way from its own tree
- C QuickJS 2026-06-04: `qjs` from the tarball checked against the sha256 of `native/build.sh`, `make qjs` (gcc 15.2.0, -O2, no `NDEBUG`, so its asserts run), run with `native/qjs-v8.js`
- Each Go side runs the files of `internal/arewefastyet/v8-v7` (the same in both trees) as `runV8` does: each file evaluated as a global script in one context, then `BenchmarkSuite.RunSuites`. `native/qjs-v8.js` takes the same steps for C QuickJS. No memory cap was set.
- 5 rounds each. The sides took turns in the same order every round: v0.30.1, v0.30.6, C QuickJS
- Raw scores of every round: [2026-11-14-v0.30.6-gcp-v8.json](2026-11-14-v0.30.6-gcp-v8.json)
